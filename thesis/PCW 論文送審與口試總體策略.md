# PCW 壓力早期預警論文：送審與口試總體策略

> 文件用途：論文送審前自我審查、模型與實驗核對、口試簡報規劃及教授備詢。  
> 研究定位：V1.x 統計式 PCW 壓力早期預警；V2.0 Machine Learning 與 V3.0 Deep Learning / Ensemble 僅列為未來研究。

---

## 一、論文最終定位

本研究不是一般時間序列預測，也不是設備故障根因診斷。研究核心是在既有 SCADA 固定工程警報之外，利用歷史壓力基準、近期壓力偏移及短期變化趨勢，辨識 PCW 壓力是否正在形成異常風險，提供操作人員額外的提前警示資訊。

### 研究核心技術

1. Statistical Drift Detection
2. Short-term Trend Forecasting
3. Multi-level Anomaly Assessment
4. Past-only Historical Replay
5. SCADA-based Early Warning Presentation

### 四項研究貢獻

| 研究貢獻 | 具體內容 | 預期價值 |
|---|---|---|
| 壓力行為偏移偵測 | 比較近期壓力與歷史基準 | 補充固定上下限監控 |
| 短期趨勢預測 | 利用近期變化率外推 | 評估接近工程警報門檻的風險 |
| 多層級風險評估 | PT、Supply/Return Branch、PCW | 從單點延伸至系統層級 |
| SCADA 整合架構 | Historian、SQL 推論、Gateway、HMI | 建立可部署的預警資料流程 |

### 研究範圍界線

- **目前研究：V1.x**，統計式壓力異常偵測與早期預警。
- **未來研究：V2.0**，Machine Learning Predictive Model。
- **未來研究：V3.0**，Deep Learning and Ensemble Model。
- 不宣稱已完成 V2/V3。
- 不取代既有 PLC 控制及 SCADA 固定工程警報。
- 不將壓力異常直接等同設備故障。
- 不假設 Supply 與 Return 存在搶水或競水現象。

#### 特徵工程

| 特徵 | 定義 | 目的 |
|---|---|---|
| Value | 當前壓力值 | 目前狀態 |
| ABS_Delta | 相鄰時間壓力變化量絕對值 | 變動幅度 |
| ABS_Jerk | 二階差分絕對值 | 變化速度的變動幅度 |
| BaseAvg60 | 歷史 60 分鐘基準平均 | 參考狀態 |
| CurrentAvg | 近期平均壓力 | 近期狀態 |
| Drift | 當前／近期值相對基準偏移 | 偵測行為改變 |
| Slope | 近期趨勢斜率 | 估計方向及速度 |
| Forecast | 指定未來時間的線性外推值 | 評估接近工程門檻的風險 |

#### T30/T20/T10 公式核對

以下公式是曾討論的模型設計示意，送審前必須逐項核對最終 Excel、Python、SQL 實作，不可只憑本文件視為最終凍結公式。

若推論時間為 \(t\)，且歷史基準定義為半開區間 \([t-70,t-10)\)，每分鐘一筆資料，則：

\[
BaseAvg60(t)=\frac{1}{60}\sum_{i=11}^{70}P_{t-i}
\]

\[
Prev5Avg=\frac{1}{5}\sum_{i=5}^{9}P_{t-i}
\]

\[
Recent5Avg=\frac{1}{5}\sum_{i=0}^{4}P_{t-i}
\]

\[
Slope=\frac{Recent5Avg-Prev5Avg}{5}
\]

若採用只保留正向趨勢的版本：

\[
Slope^+=\max(0,Slope)
\]

\[
Forecast_h=P_t+Slope^+\times h,\quad h\in\{10,20,30\}
\]

**重要模型風險：** 若研究宣稱同時預測高壓及低壓風險，必須確認下降趨勢也有對應計算，例如：

\[
Slope^-=\min(0,Slope)
\]

\[
Forecast_h^-=P_t+Slope^-\times h
\]

高壓及低壓方向應分別對應正確的工程門檻。不能只有上升趨勢公式，卻宣稱同時預測高低壓。

## 四、教授可能提出的 30 題口試問題

### A. 研究動機與學術價值

**Q1：你的研究與傳統 SCADA 固定門檻警報有什麼不同？**

建議回答：傳統 SCADA 主要依據即時壓力值是否超過工程設定門檻進行警報。本研究進一步建立歷史參考基準，分析近期壓力偏移與變化趨勢，並透過短期線性外推，評估未來是否接近工程警報門檻。因此，本研究提供固定門檻監控之外的補充性提前預警資訊，而不是取代原有警報。

**Q2：你的研究創新性在哪裡？**

建議回答：本研究的重點不是提出全新的數學演算法，而是將統計偏移偵測、短期趨勢外推及多層級風險評估，整合至半導體廠務 PCW 壓力監控情境，並設計可與既有 SCADA/Historian 架構銜接的推論流程。

**Q3：為什麼選擇 PCW？**

回答重點：PCW 是製程設備的重要冷卻水來源；供水壓力穩定性具有工程意義；具多套系統、大量分支測點及高頻時間序列資料，適合研究跨時間尺度異常行為。

**Q4：為什麼不直接使用 AI 或深度學習？**

建議回答：目前研究優先處理模型可解釋性、歷史資料可用性及工業部署需求。統計模型計算過程明確，較容易檢查每次預警的形成原因，也較容易與工程門檻及 SQL 推論流程整合。ML/DL 留待後續研究。

### B. 數學與統計模型

**Q5：為什麼使用 60 分鐘作為 Baseline？**

回答：60 分鐘作為歷史參考窗口，用來描述近期操作狀態的平均壓力水準，降低短期波動對基準的影響。必須承認，60 分鐘是研究採用的窗口設定，不代表已證明它是所有 PCW 的最佳窗口；應透過敏感度分析比較不同窗口。

**Q6：為什麼近期採用 5 分鐘平均？**

回答：以短時間區間平均降低單筆瞬間波動，再比較相鄰區間平均值，估計近期壓力變化方向及速度。

**Q7：ABS_Delta 與 ABS_Jerk 的數學意義？**

\[
\Delta P_t=P_t-P_{t-1}
\]

\[
J_t=\Delta P_t-\Delta P_{t-1}
\]

Delta 是一階差分，描述壓力變化量；Jerk 以二階差分描述變化速度的變動。絕對值衡量幅度但失去方向，因此趨勢判斷仍應保留有正負號的差分。

**Q8：為什麼使用線性預測？**

回答：本研究只進行短時間範圍的趨勢外推，不是長期壓力預測。線性模型計算簡單、解釋性高，可將近期變化率轉換為未來壓力估計，再與工程門檻比較。

**Q9：為什麼選 T-30、T-20、T-10？**

回答：三個時間尺度代表不同的提前預警距離，可觀察模型在較長、中等及較短時間範圍的預測行為。必須以實驗證據說明實際效益，不能只因名稱就宣稱成功提前 30、20、10 分鐘預警。

**Q10：為什麼不用標準差或 Z-score？**

回答：標準化統計量可作為基準偏移衡量方式，但論文必須依實際採用公式說明，不可把未實作的 Z-score 寫成模型功能。未來可透過敏感度及模型比較研究其效果。

**Q11：如何避免 Overfitting？**

回答：本研究以固定統計計算方式推論，沒有使用未來資料計算當前結果。仍須透過時間順序切分、參數敏感度分析及未參與參數設定的歷史資料評估泛化能力。

**Q12：預測結果與實際值有誤差怎麼辦？**

回答：趨勢外推是風險估計，不是未來真值保證。應以歷史回放計算 MAE、RMSE 等適用指標，並同步評估 Precision、Recall、False Alarm Rate 及 Lead Time。

### C. 廠務工程與 PCW 實務

**Q13：為什麼需要 8 套 PCW？**

回答：不同製程設備依製程需求、廠區及樓層配置，由不同 PCW 系統供應冷卻水。多套系統分別滿足各區域的冷卻需求及供水條件，因此需要分別監控各系統壓力行為。

**Q14：為什麼 Supply 與 Return 要分開分析？**

回答：兩者屬於循環系統中不同的管路與測量位置，具有不同壓力行為及工程意義，因此先分別分析，再依配對關係進行分支層級評估。

**Q15：HIHI、HI、LO、LOLO 如何設定？**

回答：這些是現場提供的工程組態設定值，研究以此作為預測結果的工程參考門檻。研究不自行宣稱這些數值由本研究推導或重新驗證為工程安全極限。

**Q16：Baseline 與 HI/LO 有什麼不同？**

回答：Baseline 代表正常操作狀態的參考壓力值；HI/LO 是現場設定的警報界線。Baseline 用於觀察行為偏移，工程門檻用於判斷是否接近或達到警報條件。

**Q17：壓力偏移但尚未超過 HI/LO，代表什麼？**

回答：代表目前壓力行為相較參考基準已發生變化，但尚未達到既有工程警報門檻。這是本研究希望提供補充性預警資訊的情境，但須透過事件回放證明其與後續風險的關聯。

**Q18：單一 PT 異常是否代表整套 PCW 異常？**

回答：不代表。單點訊號只代表該測點行為，需結合同一分支的 Supply/Return 資訊，再評估整套 PCW 狀態。

### D. 系統實作與實驗驗證

**Q19：為什麼使用 MS-SQL Agent？**

回答：Historian 已使用 MS-SQL 儲存歷史資料，可在既有資料管理架構下排程執行每分鐘推論，減少額外資料搬移及整合複雜度。

**Q20：為什麼不是 Python 每秒執行一次？**

回答：感測器每秒更新，但模型推論頻率設定為每分鐘一次。高頻資料先進入 Historian，再由排程程序取得時間窗口進行統計推論，兼顧資料保留與計算頻率。

**Q21：如何確保沒有 Data Leakage？**

回答：每個推論時間點只能使用當下已取得資料。歷史基準、近期平均及趨勢特徵均以過去資料計算，不能使用未來資料回填目前特徵。

**Q22：Modbus 是真實資料嗎？**

回答：目前 Modbus Simulator 用來模擬資料傳輸及系統整合。它可驗證資料流與預警顯示流程，但不能直接代表真實生產線壓力資料或正式現場驗收結果。

**Q23：如何證明 Excel 與 SQL 模型一致？**

回答：選取相同時間點、感測器及歷史窗口，逐項比對特徵值、趨勢斜率、Forecast 及預警結果。需保留逐筆比對紀錄，才能支持實作一致性。

**Q24：系統是否可以直接上線？**

回答：目前研究完成的是統計模型與實驗等效系統架構的設計及驗證工作。正式上線仍須完成真實資料介接、OT 網路與資安審查、現場 SAT、長時間穩定性及警報整合測試。

### E. 研究成果與限制

**Q25：模型準確率是多少？**

不可憑印象回答。必須依正式驗證資料提供 TP、FP、TN、FN、Precision、Recall、F1-score、False Alarm Rate 及 Lead Time。若尚無完整驗證結果，應明確說明已完成測試範圍及尚缺證據。

**Q26：為什麼沒有跟其他模型比較？**

回答：目前研究先確立 V1.x 統計模型的推論流程、可解釋性及工程整合方式。若資料不足以公平比較，不任意加入不同模型宣稱優劣。後續將建立一致時間切分與評估條件，再進行比較。

**Q27：操作條件改變會不會讓模型失效？**

回答：有可能。操作條件改變會影響壓力基準與近期趨勢，因此需依系統及測點建立適用工程參數，並持續評估基準偏移及誤報。

**Q28：為什麼不直接預測實際故障？**

回答：壓力異常與設備故障並非一對一關係。本研究目標是提供壓力行為異常及接近工程門檻的風險資訊，而不是直接診斷設備故障原因。

**Q29：研究實際效益是什麼？**

回答：透過歷史基準、短期趨勢及多層級風險資訊，讓廠務人員在固定工程警報發生前，取得額外壓力變化資訊，作為巡檢及操作判斷輔助。

**Q30：如果繼續研究，會做什麼？**

回答：先取得更完整真實 PCW 歷史事件及操作資料，完成長期歷史回放與現場 Shadow Mode 驗證，再比較統計參數及 Machine Learning 模型，最後評估 Deep Learning 與 Ensemble 是否帶來實際效能提升。

### 時間索引邊界特別檢查

若推論時間為 \(t\)，歷史基準採半開區間 \([t-70,t-10)\)，且每分鐘一筆資料，應包含：

\[
P_{t-70},P_{t-69},\ldots,P_{t-11}
\]

因此：

\[
BaseAvg60(t)=\frac{1}{60}\sum_{i=11}^{70}P_{t-i}
\]

不能未經核對就把索引改成 \(i=10\) 到 \(69\)，否則會產生一分鐘的邊界偏移。最終仍須以 SQL 時間戳記、Excel 公式及資料窗口實際定義為準。

## 十、最終策略與執行原則

1. **守住研究定位：** V1.x 統計式早期預警就是目前研究範圍，不加入尚未實作的 ML/DL。
2. **講透數學模型：** 教授應能從公式理解每個預警值如何產生。
3. **實驗必須完整：** 不只展示成功案例，也呈現誤報、漏報及無法預警案例。
4. **工程背景必須有依據：** 8 套 PCW 的配置、PT 感測器及工程門檻需有正式資料支持。
5. **系統落地性必須說清楚：** SQL Agent、Historian、Result Table、Modbus Gateway、Web HMI 是一條完整資料鏈，但須區分模擬與正式現場部署。
6. **避免過度宣稱：** 能證明到哪裡，就寫到哪裡；未完成的現場驗證明確列為研究限制。

> 一篇好的工程研究論文，不是把所有技術名詞都放進去，而是讓讀者清楚知道：問題是什麼、為什麼選擇這個方法、數學上如何成立、實驗如何證明，以及研究成果如何在實際環境中使用。
