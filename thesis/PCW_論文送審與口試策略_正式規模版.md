## 0. 最重要的規格鎖定：全篇唯一正式實作與驗證規模

### 0.1 正式規模

| 項目 | 正式數量／定義 |
|---|---:|
| PCW 系統 | 8 套 |
| 每套 PCW 分支配對 | 10 組 |
| 分支配對總數 | 80 組 |
| PT 壓力感測器 | 160 支 |
| PT Tag 編號 | PT-01～PT-160 |
| PT Modbus Holding Register | 40001～40160 |
| TT 溫度感測器 | 80 支 |
| FT 流量感測器 | 16 支 |
| 感測器總數 | **256 支** |

計算關係：

- 分支配對總數：8 × 10 = **80 組**
- 每組分支配對配置供水側與回水側各 1 支 PT：80 × 2 = **160 支 PT**
- 感測器總數：160 + 80 + 16 = **256 支**

### 0.2 必須杜絕的舊規模混淆

早期討論曾出現「8 套 PCW × 每套約 20 組分支配對 = 160 組分支配對 = 320 支 PT」的規劃數字。這不是本研究目前正式實作與驗證規模。

**正式論文、程式、資料庫、Register Map、HMI、實驗結果、簡報及口試回答，一律使用 8 × 10 = 80 組分支配對、160 支 PT、80 支 TT、16 支 FT。**

若有必要交代規模演進，可在研究範圍或系統設計沿革中用一句話說明早期曾評估較大規模，後續為了使 POC 與 SAT 可重現、可驗證而固定為本研究正式規模；不得將早期規模的數據混入本研究實驗結果。

### 0.3 160 支 PT 與 Modbus 位址的映射規則

| Tag 範圍 | Holding Register 顯示位址 | 數量 |
|---|---|---:|
| PT-01 | 40001 | 1 |
| PT-02 | 40002 | 1 |
| … | … | … |
| PT-160 | 40160 | 1 |
| **合計** | **40001～40160** | **160** |

需在正式 Register Map 中逐筆列出 PT-01～PT-160 的完整對照，不可只用範圍敘述取代可追溯的 Tag Master。

**Modbus 位址注意事項：** 40001 常是文件使用的參考位址表示法；部分函式庫實際讀寫時使用從 0 開始的 PDU offset。因此，不能僅憑畫面顯示 40001 就認定底層傳輸 offset 必然是 40001。應以實際使用的 Modbus 函式庫、設備或模擬器文件為準，執行讀寫驗證，並在文件中分別記錄「人類可讀的 4xxxx 位址」與「函式庫使用的 offset」。

### 0.4 正式規模一致性檢查

送審前全專案搜尋以下關鍵字與數字：

## 1. 研究定位：口試時先把研究問題說清楚

### 1.1 本研究要解決的問題

本研究以 PCW（Process Cooling Water，製程冷卻水）壓力時間序列為主要分析對象，探討如何在傳統固定上下限警報之外，增加兩類具有提前量的資訊：

1. **行為偏移／漂移偵測（Behavior Shift / Drift Detection）**：辨識壓力資料相對於歷史正常參考行為是否出現持續性偏移。
2. **越限時間估計（Time-to-Limit Estimation）**：在資料品質與趨勢條件允許時，估計壓力朝 HI 或 LO 限值移動的剩餘時間。

研究重點不是宣稱已經能準確預測所有設備故障，也不是取代既有 PLC 保護、硬體 interlock 或 SCADA 原始警報，而是建立一個可解釋、可追溯、可重現的早期異常分析與預警驗證方法。

### 1.2 研究問題（Research Questions）建議

- **RQ1：** 在固定 HI/LO 門檻尚未觸發前，能否利用歷史參考視窗與近期觀測視窗，辨識 PCW 壓力行為的持續偏移？
- **RQ2：** 在資料品質、趨勢方向及模型適用條件成立時，能否估計壓力到達 HI 或 LO 門檻的時間？
- **RQ3：** 如何將感測器資料、虛擬 PLC Register、資料庫、推論結果及 Web HMI 串接，形成可重現的 POC 與 SAT 驗證流程？
- **RQ4：** 如何區分原始上下限警報與模型預測警示，並確保資料品質不足、預測過期或模型失效時不輸出誤導性結果？

### 1.3 研究貢獻應採保守且可證明的表述

可主張的貢獻：

- 建立一套面向 PCW 壓力時間序列的偏移候選偵測與越限時間估計流程。
- 將統計分析、資料品質判斷、推論結果管理及 HMI 呈現整合成可重現的實驗架構。
- 建立原始警報與模型預測警示分離的資料及事件管理方式。
- 透過 POC/SAT 測試案例驗證資料更新、推論排程、結果有效期限、恢復情境及版本追溯。

避免使用下列未經證據支持的說法：

- 「可準確預測設備故障」
- 「可完全避免 PCW 異常」
- 「已部署於實際廠務控制系統」
- 「可取代 SCADA／PLC 警報」
- 「模型可保證提前 N 分鐘預警」
- 「所有 PCW、所有製程條件均適用」

## 2. 雙層式 Fab 與 PCW 系統配置：概念邊界要交代清楚

### 2.1 雙層式 Fab 的描述原則

本研究場景為雙層式 Fab。論文應清楚區分三個不同概念：

1. **建築樓層配置：** Fab 有上下兩層的空間與設備配置。
2. **PCW 系統數量：** 本研究實作與驗證設定為 8 套 PCW。
3. **每套 PCW 的分支配對數：** 本研究設定每套 10 組，共 80 組。

不可因為 Fab 有兩層，就未經設備配置圖或工程資料佐證而推論每層必定配置 4 套 PCW。若實際樓層與 PCW 供應區域的對應尚未取得可公開或可引用的工程證據，應將圖示標為「研究用概念配置」或「實驗系統邏輯架構」，不要冒稱為實際廠區竣工配置。

### 2.2 建議圖示

建議準備兩張不同用途的圖，避免一張圖同時表達太多層次：

- **圖 A：雙層式 Fab 概念配置圖**：呈現兩層空間、設備區與 PCW 供應關係；若樓層分配未經確認，明確註記為概念示意。
- **圖 B：本研究實作與驗證規模圖**：8 套 PCW，每套 10 組分支配對；每組有供水側與回水側 PT，總計 160 支 PT；另有 80 支 TT、16 支 FT。

圖 B 應附上總數計算，且與 Tag Master、資料庫筆數、Register Map 及 HMI 顯示一致。

### 2.3 感測器角色

- **PT：** 本研究主要分析變數，用於供水側／回水側壓力時間序列。
- **TT：** 溫度監測變數，可作為系統狀態描述、輔助分析或後續研究變數；若本研究模型未使用 TT，應明確寫成「監測／情境資訊」，不得暗示已納入模型特徵。
- **FT：** 流量監測變數；若本研究模型未使用 FT，同樣應明確區分「系統配置」與「實際模型輸入」。

**重要：** 感測器數量不等於模型特徵數量。論文必須分別列出系統感測器總量、實際收集欄位、模型輸入欄位及模型輸出欄位。

## 3. 系統架構與資料流：用可驗證的簡化等效架構

### 3.1 研究限制與架構選擇

因資訊安全與實際環境限制，本研究不以連接公司正式廠務控制網路或修改實際 SCADA/PLC 為前提；使用簡化等效架構完成模型分析、資料交換與展示驗證。

建議用語：

> 本研究採用模擬感測資料、虛擬 PLC Register、資料庫及 Web HMI 建立簡化等效實驗平台，以驗證資料擷取、原始門檻判斷、週期性推論、預測結果回寫及警示呈現等流程。此架構用於研究方法與概念驗證，不代表已完成實際廠務 SCADA/PLC 的正式部署或控制整合。

### 3.3 取樣與推論週期

目前研究設計的基準為：

- 感測器資料：每秒取樣一次（1 Hz），前提是模擬器與資料紀錄程式確實依此週期執行。
- 原始資料／Historian：以秒級時間戳記記錄；若實際資料庫並非每個 Tag 每秒一筆，必須按實際紀錄描述。
- 模型推論：每分鐘執行一次（1-minute scheduled inference），需以排程紀錄或執行 log 證明。
- HMI：顯示最新有效資料、原始警報與模型預測結果；更新頻率需以實測為準，不可直接假定等於感測器取樣頻率。

若 PT 160 支皆以 1 Hz 記錄，理論上每秒 PT 樣本數為 160 筆；每分鐘為 9,600 筆 PT 樣本。這是容量估算，不代表資料庫實際筆數，實際筆數應扣除停機、缺值、品質不良與未成功寫入資料。

## 4. 模型方法與數學定義

> 本節提供論文可採用的模型定義框架。正式送審前，必須逐式核對程式碼、參數檔與實驗結果。若實際程式使用不同視窗、不同尺度估計或不同有效性規則，應以實際實作修正文句及公式。

### 4.1 資料視窗

令某一 PT Tag 的離散壓力序列為：

\[
x_1,x_2,\ldots,x_t
\]

建立歷史參考視窗 \(W_{ref}\) 與近期觀測視窗 \(W_{recent}\)。兩個視窗需有明確長度、時間範圍、更新方式及資料品質規則。

- \(W_{ref}\)：代表已確認或選定的參考狀態。
- \(W_{recent}\)：代表近期待檢查的觀測狀態。

不能只寫「比較歷史與近期資料」，必須在方法章列出視窗長度、取樣頻率、滑動方式及最少有效樣本數。

### 4.2 Robust Statistics：Median 與 MAD

參考視窗中位數：

\[
m_{ref}=\operatorname{median}(W_{ref})
\]

Median Absolute Deviation：

\[
MAD_{ref}=\operatorname{median}(|x_i-m_{ref}|)
\]

以常態分布一致性係數建立 robust scale：

\[
s_{ref}=1.4826\times MAD_{ref}
\]

偏移分數可定義為：

\[
D_t=
\frac{
|\operatorname{median}(W_{recent})-m_{ref}|
}{
\max(s_{ref},\epsilon)
}
\]

其中：

- \(D_t\)：近期視窗相對於參考視窗的標準化偏移程度。
- \(\epsilon\)：避免分母為 0 的極小正數。
- 1.4826：在常態分布假設下，使 MAD 對應到標準差尺度的係數。

**解釋限制：**

- \(D_t\) 是偏移程度分數，不是故障機率。
- 單次高分不必然代表異常；可搭配連續次數、持續時間、資料品質及工程門檻判定。
- 若參考視窗 MAD 為 0 或接近 0，應有明確的尺度下限或品質處理規則。
- 參考視窗必須避免混入警報期間、異常期間及尚未恢復的資料，否則正常基準會被污染。

### 4.3 偏移候選狀態判定

可用下列概念表達連續條件：

\[
DriftCandidate_t =
\begin{cases}
1, & D_t>\theta_D \text{ 且符合持續性條件}\\
0, & \text{其他情況}
\end{cases}
\]

其中 \(\theta_D\) 為偏移門檻，持續性條件可由連續 \(k\) 次成立、指定時間比例或其他已實作規則定義。

必須在論文交代：

- \(\theta_D\) 如何設定（工程設定、訓練資料校準或驗證集選定）。
- \(k\) 或持續時間條件為何。
- 是否有 hysteresis（進入與解除門檻不同）。
- 偏移解除是否需連續穩定一段時間。
- 如何處理感測器跳點、缺值與資料中斷。

不要只用漂亮的公式，卻沒有實際參數、程式對應及選值依據。

### 4.4 越限時間估計：局部線性趨勢基準模型

在指定近期視窗內，建立局部線性模型：

\[
x(t)=a+bt+\varepsilon_t
\]

其中：

- \(a\)：截距。
- \(b\)：壓力變化斜率。
- \(\varepsilon_t\)：模型殘差。
- \(b\)：可由最小平方法或程式實際採用的估計方式求得。

若趨勢朝 HI 門檻移動且 \(b>0\)：

\[
T_{HI}=\frac{HI-x_t}{b}
\]

若趨勢朝 LO 門檻移動且 \(b<0\)：

\[
T_{LO}=\frac{LO-x_t}{b}
\]

第二式在 \(x_t>LO\)、\(b<0\) 時會得到正的剩餘時間。輸出時應明確標示時間單位，例如秒或分鐘。

**不可輸出有效預測的情況：**

- 斜率接近 0，無法可靠估計越限時間。
- 斜率方向與目標門檻不一致。
- 資料點數不足、缺值比例過高或品質旗標不良。
- 擬合品質低於預設要求。
- 計算結果為負值、非有限值或超出合理預測範圍。
- 目前值已經越限；此時應由原始警報機制呈現，不應把負的預測時間當成提前預警。
- 預測結果超過有效期限。

遇到上述情況，應輸出 `Unknown`、`Invalid` 或其他明確的無效狀態，而不是硬湊出一個時間數字。

### 4.5 HIHI／HI／LO／LOLO 門檻

研究討論曾出現 HIHI=1.8、HI=1.7、LO=1.3、LOLO=1.2 等示例值。**這些數值不可未經核對就宣稱適用於全部 160 支 PT 或全部 PCW。**

送審前應建立正式 Limit Configuration：

| 欄位 | 要求 |
|---|---|
| tag_id／group_id | 說明門檻適用對象 |
| HIHI / HI / LO / LOLO | 實際設定值及單位 |
| source | 工程規格、既有設定或研究假設 |
| effective_from | 生效時間 |
| config_version | 設定版本 |
| approved_by／evidence | 若有核准或佐證，記錄來源 |

若因資料保密不能公開實際廠務設定，應採去識別化或研究用設定，並清楚標示「實驗門檻」而非實廠設定。

### 4.6 供回水壓差

可定義：

\[
\Delta P=P_{supply}-P_{return}
\]

但本研究不應自行假設供水與回水兩側存在「競爭」或互斥關係。若模型分別分析供水與回水 PT，應各自保留其 Tag 與時間序列；若分析壓差，則將 \(\Delta P\) 作為衍生變數，並交代兩側時間戳對齊、缺值處理與單位一致性。

除非有明確工程依據及實驗驗證，不要把供回水壓差變化直接等同於設備故障。

## 5. 資料品質、訓練資料與資料洩漏防範

### 5.1 Quality Flag

至少應考慮：

- GOOD：資料有效且通過基本範圍檢查。
- MISSING：缺值。
- STALE：資料時間戳過舊。
- OUT_OF_RANGE：超出合理工程範圍。
- COMM_ERROR：通訊或擷取失敗。
- INVALID：其他無法供模型使用的資料。

名稱可依程式調整，但論文、資料庫與 HMI 必須採一致定義。

### 5.2 正常參考資料與異常資料

正常參考視窗不應把警報發生後至恢復前的資料當成正常資料重新納入基準。建議明確定義：

- 正常資料的選取條件。
- 原始警報前後的排除區間。
- 恢復後需要多少穩定時間才能重新納入參考基準。
- 資料品質不佳時是否暫停更新參考基準。
- 參考基準是否凍結、定期更新或採滑動更新。

### 5.3 時序資料切分

採時間順序切分，不可隨機打散造成未來資訊洩漏：

```text
Earlier period        Gap / Purge        Later period
Train                 Excluded           Validation
                                         |
                                         Gap / Purge
                                         |
                                         Test
```

- Train：模型參數估計或正常參考基準建立。
- Validation：門檻、視窗或超參數選定。
- Test：最終效能評估，只在模型與設定固定後使用。
- Gap/Purge：避免相鄰視窗重疊或標籤時間範圍交疊造成洩漏；間隔長度至少應考量最大特徵視窗及預測標籤涵蓋範圍。

若資料量不足以進行多段切分，應如實說明限制，採用適當的時間序列驗證策略，不可宣稱一般化能力已充分證明。

### 5.4 異常樣本與標籤定義

若使用人工注入異常或模擬越限情境，必須交代：

- 注入方式、幅度、持續時間及起始時間。
- 異常類型與真值標籤如何產生。
- 模擬異常與實際現場異常的差異。
- 是否有多種斜率、階躍偏移、緩慢漂移、尖峰、缺值及雜訊情境。
- 評估結果只代表指定模擬情境，不應外推為實廠故障預測準確率。

## 6. 評估指標與實驗設計

### 6.1 偏移偵測

若有可靠標籤，可報告：

- Precision
- Recall
- F1-score
- False Positive Rate
- False Alarm Count
- Detection Delay（從異常開始到首次偵測的時間）

若沒有足夠可信的真實標籤，不應只為了產生數字而計算分類指標。可改報告案例分析、偏移分數趨勢、警示觸發時間與人工標記的一致性，並明確揭露標籤限制。

### 6.2 越限時間估計

對於有可計算真實越限時間的模擬案例，可評估：

\[
Error_i = |\hat{T}_i-T_i|
\]

並視資料適用性報告 MAE、Median Absolute Error、RMSE 或相對誤差。應同時報告：

- 有效預測覆蓋率（coverage）。
- 預測有效／無效比例。
- 預測時間誤差。
- 不同斜率、雜訊及資料品質情境下的結果。
- 提前量是否足夠，以及預測是否過度頻繁變動。

不可只挑成功案例報告誤差，卻隱藏大量 Unknown 或 Invalid 的情況。

## 11. 教授可能提出的問題與建議回答

以下回答是答題框架，必須依實際程式、參數及結果補上真實數據，不可背誦不存在的效能數字。

### A. 研究動機與貢獻

**Q1：你的研究究竟要解決什麼問題？**

答：本研究要補足固定上下限警報對越限前行為變化描述不足的問題，聚焦於壓力行為偏移候選偵測，以及在條件允許時估計到達 HI/LO 門檻的時間。研究成果是輔助分析方法與可重現驗證流程，不是故障診斷或控制系統替代品。

**Q2：既有 HI/LO 警報已經存在，為何還需要你的方法？**

答：HI/LO 是明確的門檻事件；本研究希望在越限前增加趨勢與偏移資訊。兩者功能不同，原始警報仍保留為主要門檻監控機制，模型輸出只提供輔助預警資訊。

**Q3：你的創新性在哪裡？Median/MAD 和線性回歸都不是新方法。**

答：本研究不主張發明新的統計演算法。研究價值在於針對 PCW 壓力監控情境，定義參考／近期視窗、偏移候選判斷、越限時間估計的適用條件，並整合資料品質、原始警報與預測警示分離、結果有效期限及 POC/SAT 可追溯驗證。若委員要求學術創新強度，應以文獻比較與實驗結果具體說明，而非只宣稱方法新穎。

**Q4：你偵測的是故障，還是統計偏移？**

答：本研究直接偵測的是相對於參考行為的統計偏移候選，不等同於設備故障。要確認故障原因，仍需工程診斷、設備資訊與現場驗證。

### B. 研究規模與 Fab 配置

**Q5：為何是 8 套 PCW、每套 10 組分支？**

答：這是本研究為了建立可管理、可重現的實作與驗證平台所固定的實驗規模。它定義研究平台的 Tag、資料與測試範圍，不應被誤述為所有實際 Fab 的通用配置。

**Q6：為什麼 80 組分支配對會有 160 支 PT？**

答：每組分支配對分別量測供水側與回水側壓力，各配置一支 PT，因此 80 × 2 = 160 支 PT。

**Q7：160 支 PT 的位址如何對應？**

答：PT-01 至 PT-160 依序對應文件顯示的 Modbus Holding Register 40001 至 40160。正式實作另需核對函式庫實際使用的零起始 offset，並以讀寫測試證明映射正確。

**Q8：為什麼還有 80 支 TT 與 16 支 FT？模型有用到嗎？**

答：它們是本研究平台的監測配置。若目前模型只使用 PT 壓力序列，應明確說明 TT/FT 尚未納入主要模型輸入，不能因為系統有配置就宣稱已進行多變量模型分析。

**Q9：雙層 Fab 是否代表每層各有 4 套 PCW？**

答：不一定。建築樓層數、PCW 系統數與供應區域配置是不同層次。本研究固定 8 套 PCW 作為實驗規模；若沒有工程圖佐證，不推論每層的實際套數分配。

**Q10：早期文件為什麼出現 320 支 PT？**

答：那是早期曾評估的較大規模規劃，並非本研究目前正式實作與驗證規模。正式版本已統一為 8 × 10 = 80 組分支配對、160 支 PT，並以 Tag Master、Register Map、資料庫及實驗紀錄作一致性核對。

### C. 模型與參數

**Q11：為什麼用 Median 而不是 Mean？**

答：Median 對少數極端值較不敏感，適合在可能有尖峰或離群點的壓力序列中描述視窗中心位置。但它不代表可以忽略資料品質或所有異常型態。

**Q12：MAD 為何乘上 1.4826？**

答：在常態分布假設下，1.4826 是將 MAD 換算到與標準差相同尺度的常用一致性係數。這是尺度校正，不代表資料必然服從常態分布。

**Q13：偏移分數是否代表異常機率？**

答：不是。它是近期視窗相對於參考視窗的標準化偏移程度。若要轉換為機率，必須另外建立機率模型並用獨立資料校準。

**Q14：為何需要連續性條件？**

答：單點尖峰可能來自雜訊或瞬時擾動。加入連續次數或持續時間條件，可降低單點觸發造成的誤報；但條件太嚴格也可能增加偵測延遲，因此要透過驗證集評估取捨。

**Q15：參考視窗如何避免被異常資料污染？**

答：需要依原始警報、品質旗標及恢復狀態排除異常期間，並設定恢復後的穩定條件；資料品質不佳時不更新參考基準。實際排除規則與程式必須一致。

**Q16：為何使用線性模型估計越限時間？**

答：本研究把它定位為可解釋的局部基準模型。若短時間視窗內趨勢近似線性，斜率可用來估計到達門檻的時間；若趨勢非線性、斜率方向不符或擬合品質不足，就不輸出有效預測。

**Q17：線性模型預測很遠的未來會不會不準？**

答：會有風險。因此預測只適用於局部趨勢近似線性的短期估計，應設定最大預測範圍、品質門檻與有效期限，並將結果視為估計而非保證。

**Q18：斜率接近零怎麼處理？**

答：當斜率低於設定的最小有效幅度，時間估計會對微小斜率非常敏感，因此應輸出 Unknown/Invalid，而不是產生極大的時間值。

**Q19：HIHI、HI、LO、LOLO 的門檻怎麼決定？**

答：應依正式工程設定或研究用實驗設定及其來源決定，並記錄適用 Tag、單位與版本。若目前只使用示例值，必須明確標示為研究假設，不可宣稱是所有 PCW 的實際設定。

### D. 資料與驗證

**Q20：如何避免資料洩漏？**

答：採時間順序切分，訓練、驗證與測試期間不隨機混合；視窗重疊及預測標籤涵蓋範圍需以 gap/purge 控制。最終測試集不參與門檻或模型參數調整。

**Q21：正常資料如何定義？**

答：需根據資料品質、原始警報、事件區間與恢復條件定義。不能單純把沒有超過 HI/LO 的所有資料都視為正常，因為越限前可能已存在偏移。

**Q22：若沒有足夠真實故障資料，如何證明有效？**

答：可用可控的模擬情境驗證演算法對指定偏移型態與趨勢的反應，並清楚界定結論只適用於這些實驗情境。缺少實廠標籤是研究限制，不能把模擬準確率宣稱為實廠故障預測準確率。

**Q23：如何證明每秒取樣與每分鐘推論真的執行？**

答：以帶時間戳的原始資料、排程 log、推論結果表及連續測試紀錄佐證。畫面刷新不能單獨證明資料庫每秒寫入或模型每分鐘執行。

**Q24：模型預測錯誤或資料過期怎麼辦？**

答：資料品質或預測有效性不成立時，輸出 Unknown/Invalid/Expired 狀態，並顯示最後更新時間與原因；不可繼續把舊預測當成最新有效結果。

**Q25：原始警報與預測警示如何區分？**

答：原始警報由即時量測值與固定門檻判斷，使用獨立 raw_event_id；預測警示由模型推論產生，使用 inference_id，並有自己的品質狀態與 valid_until。兩者不共用同一事件生命週期。

### E. 系統與實務應用

**Q26：為何不用真正 SCADA？**

答：受到實際環境資訊安全及設備安裝限制，本研究以模擬感測器、虛擬 PLC Register、SQL 與 Web HMI 建立簡化等效平台，重點在驗證分析方法與資料流程。實際 SCADA 整合屬後續工程工作。

**Q27：這套系統能否直接控制 PCW？**

答：不能。本研究是監控輔助分析與預警概念驗證，不發出控制命令，不取代 PLC interlock 或既有安全機制。

**Q28：HMI 網頁能開啟，是否代表系統完成？**

答：不能。頁面可連線只證明入口可存取，還需分別驗證資料更新、後端持久化、推論排程、Register 回寫、事件管理及畫面狀態。未取得測試證據的功能應列為待驗證。

**Q29：若未來擴展到更多 PCW 或更多 Tag，如何處理？**

答：以 Tag Master 與設定驅動方式管理 PCW、branch、sensor、register mapping 與門檻，避免將 Tag 數量硬編碼在模型程式中；擴展前仍需做容量、資料品質、版本與效能測試。

**Q30：本研究最大的限制是什麼？**

答：主要限制包括使用模擬／簡化等效環境、缺乏足量且可標記的實廠故障資料、局部線性模型對非線性趨勢的限制，以及模型跨 PCW／跨設備泛化能力仍需更多實際資料驗證。

## 14. 最終一致性原則

論文中每一項主張都應能連到至少一種證據：

| 論文主張 | 對應證據 |
|---|---|
| 本研究有 8 套 PCW | Tag Master／系統設定 |
| 每套 10 組分支配對 | Branch Master／配置表 |
| 有 160 支 PT | PT Tag 清單及資料筆數 |
| PT 對應 40001～40160 | Register Map 及讀寫測試 |
| 每秒取樣 | 原始資料時間戳與紀錄統計 |
| 每分鐘推論 | Scheduler log 與 inference table |
| 可偵測偏移 | 偏移案例、輸出與評估結果 |
| 可估計越限時間 | 趨勢案例、真值越限時間與誤差 |
| 有資料品質保護 | Quality Flag 與 Unknown/Invalid 案例 |
| HMI 顯示正確 | HMI 截圖與後端資料對照 |
| 系統流程可重現 | POC/SAT 測試紀錄 |

### 送審核心守則

1. **規模唯一：** 8 PCW × 10 組 = 80 組；PT 160、TT 80、FT 16，總計 256 支感測器。
2. **方法一致：** 論文公式、程式實作、參數設定與實驗結果必須一致。
3. **資料可信：** 時序切分、資料品質與異常期間排除必須交代清楚。
4. **功能有證據：** 網頁能開啟不等於整套系統完成；每項功能都要有測試紀錄。
5. **主張不超過證據：** 模擬驗證不等於實廠部署；偏移偵測不等於故障診斷；時間估計不等於保證提前預警。
6. **口試先答結論：** 以研究問題、方法、證據、限制的順序回答。
