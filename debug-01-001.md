# Debug Log: PCW SCADA Modbus Simulator & Prediction Engine (debug 01-001)

## Issue 1: Simulator Settings Not Persisting
**Symptom**: Values (Base Value, Noise) entered in the Modbus Simulator reset immediately after leaving the simulator page.
**Root Cause**: The simulator settings in `SimulatorEngine` were only stored in the local component state or were overwritten by default `MockDatabase` initialization without persisting to a global store (Zustand/localStorage).
**Resolution**: 
- Moved `simulatorConfigs` into `MockDatabase` and persisted to `localStorage` under `pcw_sim_configs`.
- Updated `PcwDataService.updateSimulatorConfig` to save changes immediately.
- Refactored `ModbusMonitor.tsx` to read the configs on mount and when tags are selected.

## Issue 2: Live Value vs Prediction Value Mismatch
**Symptom**: The "Live Value" shown in the Modbus Simulator did not match the "Current Value" shown in the System Prediction (T-30) Engine.
**Root Cause**: The Prediction Engine was taking point-in-time snapshots of the data (`p.currentValue`) and storing them, while the UI was rendering that static snapshot instead of mapping it back to the live `SensorRepository`.
**Resolution**: 
- In `PredictionT30.tsx`, decoupled the `currentValue` rendering from the static snapshot.
- Added live lookup: `const liveSensor = sensors.find(s => s.tagId === p.tagId); const liveValue = liveSensor ? liveSensor.value : p.currentValue;`.
- Ensured all views rely on a single source of truth for live values.

## Issue 3: Leftover UI Clutter (Drift, Quality, Comm Loss)
**Symptom**: The user requested a "cleaner" simulator UI without `Drift Slope`, `Bad Quality`, `Comm Loss`, `Step Change`, or `Spike`.
**Root Cause**: Legacy code from a previous complex simulation model was still present in `SimulatorEngine.ts`, `MockDatabase.ts`, `modbusTypes.ts`, and `ModbusMonitor.tsx`.
**Resolution**: 
- Completely deleted all references to these variables across the entire stack.
- Removed columns from the active simulator tags table.
- Verified TypeScript compilation using `npm run build` after interface changes.

## Issue 4: Simulator UI Layout Reorganization
**Symptom**: The left panel and right panel felt disconnected, with filters scattered across the top of the data table.
**Root Cause**: The table header contained duplicate filtering controls (`System`, `Submain`, `Sensor Type`) that were not intuitive when performing bulk updates.
**Resolution**: 
- Re-architected `ModbusMonitor.tsx` to a pure Side-by-Side (`flex: 1`) layout.
- Moved all search and filter dropdowns into the Left Control Panel under "1. Select Tags to Modify".
- Cleaned the right panel to show only the pure HTML table of sensor values.
